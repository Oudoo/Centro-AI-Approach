Executive Overview

Centro CDX AI Recruiter is a standalone Next.js 15 web application that automates the initial screening stage of BPO candidate recruitment. It replaces the traditional manual phone-screen workflow with an AI-led, 5-minute voice interview conducted by "Maya", a Hume AI EVI 2 voice agent, combined with real-time facial expression analysis and post-session rubric scoring via Anthropic Claude Sonnet 4.6.

🎯

Problem Statement

Centro CDX screens 200+ BPO candidates monthly. Manual phone screens take ~15 min/candidate, are subjective, and create a 3-day bottleneck before onboarding.

⚡

Solution

A self-service, 5-minute AI screening that runs 24/7, scores candidates on a standardized rubric, and auto-syncs results to Zoho Recruit for recruiter review.

📊

Key Metrics

  • Screen time: 15 min → 5 min
  • Recruiter review: 10 min → 2 min
  • Rubric consistency: ~65% → ~95%
  • Capacity: unlimited concurrent
ℹ️

Scope: This document covers the v1.0 production architecture and the planned phases through v2.0. The system is designed for Centro CDX's Egypt + Jordan operations, screening Customer Service, Technical Support, and Back Office roles in English.

Stage Breakdown

1. Landing & Consent

/ — Collects name, email. Requires two consent checkboxes: recording consent and network stability acknowledgment. Live network ping indicator refreshes every 4 seconds.

2. Identity Verification

/verify/[sessionId] — Two-image flow: National ID photo upload + live selfie capture. AWS Rekognition CompareFaces enforces ≥85% similarity. OCR → Claude transliterates Arabic name to English. Creates audit trail for identity fraud prevention.

3. AI Voice Screening

/screen/[sessionId] — Hume EVI 2 WebSocket session. Maya runs a 5-segment structured interview: Intro → Read-Aloud → Situational → Role-Play (angry customer) → Scheduling. WebRTC audio + webcam recording via MediaRecorder API.

4. Post-Session Scoring

/api/score — Claude Sonnet 4.6 scores the transcript on 4 weighted dimensions (Fluency 20%, Composure 30%, EQ 25%, Confidence 25%). Claude Vision analyzes face frames for expression timelines. Fuzzy name matching catches CV/ID discrepancies.

5. Zoho Sync

Session data, scores, and rationale are POSTed to Zoho Creator's Screening_Session form via OAuth2 refresh-token flow. Silent-fail design — candidate never sees Zoho errors.

6. Results Display

/results/[sessionId] — Candidate-facing score breakdown with dimension cards, per-segment notes, methodology panel, emotion timeline chart, and the full AI rationale.

5.4 Facial Expression Analysis

Webcam frames are captured every ~10 seconds during the screening, yielding 30-40 frames per session. Two analysis providers are implemented:

Claude Vision (Primary — v1.0)

Frames sent in batches of 6 to Claude Sonnet 4.6 Vision. Analyzes: Joy, Calmness, Confidence, Engagement, Anxiety, Interest, and 10 more micro-expressions on a 0.0–1.0 scale. Results corroborate Composure and Confidence rubric dimensions.

lib/claude-face.ts

Hume Expression Measurement (Backup)

Frames streamed to Hume's Expression Measurement WebSocket API. Uses burst-and-backpressure send pattern (4 initial, then 1-per-response). Provides an alternative emotion taxonomy.

lib/hume-face.ts

Integration Details

🔊 Hume AI

  • EVI 2: WebSocket voice agent with persona prompt
  • Auth: OAuth2 Client Credentials → short-lived token
  • Config ID: Pre-configured in Hume Platform dashboard
  • Output: Transcript + prosody emotions per turn
  • Module: lib/hume.ts

🧠 Anthropic Claude

  • Model: Claude Sonnet 4.6 (claude-sonnet-4-6)
  • Uses: Scoring, face analysis, CV parsing, ID parsing
  • Auth: API key in header
  • Max tokens: 6000 (scoring), 3000 (CV), 2000 (face), 1000 (ID)
  • Module: lib/claude.ts, lib/claude-face.ts, lib/cv-parser.ts

👁 AWS Rekognition

  • Region: eu-central-1 (Frankfurt) — closest to Egypt
  • APIs: CompareFaces, DetectText, DetectFaces
  • Threshold: 85% similarity (configurable)
  • Max image: 5MB per image (direct bytes)
  • Module: lib/aws-rekognition.ts

🔵 Zoho Creator

  • API: REST v2.1
  • Auth: OAuth2 refresh token → access token (cached 50 min)
  • Forms: Screening_Session, AI_Config
  • Multi-region: us, eu, in, au, jp, sa
  • Module: lib/zoho-creator.ts (1152 lines)

📁 Zoho WorkDrive

  • API: REST v1 upload endpoint
  • Auth: Reuses Creator's OAuth token (same Zoho One workspace)
  • Purpose: Store session recording WebM files
  • Response: File ID + permalink
  • Module: lib/zoho-workdrive.ts

📞 Genesys Cloud

  • API: Agentless Outbound Messaging
  • Channel: WhatsApp
  • Auth: OAuth2 Client Credentials
  • Template: Optional — falls back to raw message body
  • Module: lib/genesys.ts

Storage Architecture

🗄 Zoho Creator (Primary SoR)

Screening_Session form — all scored sessions synced via REST API. 35+ fields including scores, transcript, verification data, reviewer overrides. AI_Config form stores the active rubric for hot-reloading without redeployment.

📁 Local File DB (Fallback)

data/sessions.json — file-system JSON store via lib/local-db.ts. Primary write target in v1.0. Ensures sessions are never lost even if Zoho Creator sync fails.

💾 IndexedDB (Client-Side)

Two object stores: recordings (session WebM blobs, ~20-30MB each) and usage_log (per-session consumption metrics). DB version 2. Auto-recovery on version mismatch.

🔐 Authentication

  • Admin: Shared TA-team credentials (POC)
  • Session: HMAC-SHA256 signed cookie, 12h TTL
  • Edge-safe: Web Crypto API only (no node:crypto)
  • Constant-time: Signature comparison prevents timing attacks
  • Planned: Zoho One SSO (Phase 1.5)

🛡 Data Protection

  • ID images: Not retained — processed in-memory only
  • Secrets: All in .env.local, never committed
  • Production: Vercel environment variables
  • Rekognition: eu-central-1 region for GDPR proximity
  • Consent: Explicit opt-in before recording starts

🤖 AI Safety

  • Prompt injection: Maya's system prompt has strict SAFETY block
  • Persona lock: Candidate inputs treated as data, never instructions
  • Off-topic: Maya redirects all non-interview questions
  • Profanity: Auto-terminates on abusive language
  • Role-play containment: Only the defined scenario runs
